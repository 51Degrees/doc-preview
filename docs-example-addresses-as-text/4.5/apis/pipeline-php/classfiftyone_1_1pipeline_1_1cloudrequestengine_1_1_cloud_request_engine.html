Detailed Description

Engine that makes a call to the 51Degrees cloud service.

Returns raw JSON as a "json-response" property under the "cloud-response" dataKey.

◆ __construct()

fiftyone\pipeline\cloudrequestengine\CloudRequestEngine::__construct ( array $settings)

Settings should contain a resourceKey, a licenseKey or both, and optionally: 1) requestedProperties, the fully qualified names of the properties to ask for, as an array or one comma separated string.

Required with a licenseKey on its own. Beside a resourceKey the cloud service adds them to the properties the resource key carries. 2) a cloudEndPoint, the address of the cloud service. When it is blank, the _51DEGREES_CLOUD_ENDPOINT environment variable is used, and when that is blank too, the default address. Blank means unset, empty or only whitespace. 3) a cloudRequestOrigin to use when sending requests to cloud. 4) discoveryResults, what getDiscoveryResults() gave after an earlier build with the same keys and cloudEndPoint, so that the engine asks the cloud service for nothing when it is built.

Without discoveryResults the engine asks the cloud service for its accessible properties and its accepted Evidence keys when it is built. A 4xx answer, such as for a resource key the cloud service does not accept, is thrown. Any other failure is logged as a warning once the engine is in a pipeline, and the request is made again when the engine is first used.

The timeoutSeconds setting is the timeout of each request to the cloud service, 2 seconds unless set. A given httpClient keeps its own timeout unless the setting is given.

◆ getContent()

fiftyone\pipeline\cloudrequestengine\CloudRequestEngine::getContent ( FlowData $flowData)

Generate the Content to send in the POST request.

One name under several prefixes is sent once, with the value of the prefix that evidence.md ranks highest, being query, header, cookie, server, fiftyone and location, then any other prefix alphabetically. The groups are added lowest precedence first, so a later value replaces an earlier one, and a replacement by a key other than a query key is raised as a warning.

Every Evidence value goes in, including a value no element in the Pipeline accepts, because what the cloud service uses changes over time. The reserved names, and any value under the web request view's key, are left out by addQueryData. The view itself is never in the Evidence values.

Returns
array<string, int|string>

◆ getDiscoveryResults()

fiftyone\pipeline\cloudrequestengine\CloudRequestEngine::getDiscoveryResults ( )

The discovery results, being the accessible properties and the accepted Evidence keys, which depend only on the keys and the cloud endpoint.

Pass them as the discoveryResults setting to build an engine with the same keys and endpoint without asking the cloud service. They hold no key, and can be stored as JSON. Null until both have been obtained.

Returns
null|array{credentials: string, evidenceKeys: array<string>, accessibleProperties: array<string, array<string, array<string, mixed>>>}

◆ getEvidenceKeyFilter()

fiftyone\pipeline\cloudrequestengine\CloudRequestEngine::getEvidenceKeyFilter ( )

Instance of EvidenceKeyFilter of the evidence keys the cloud service lists.

The keys are asked for when the engine is built. Where that failed, they are asked for again the first time they are needed, which is when the first Evidence is set, so that the Evidence the cloud service uses is kept. A failed request leaves the list empty, and processInternal reports the failure.
