Non blocking check for new data, which update polling uses.

The thread has no caller to pass a failure to, so a failure is logged with the message of its row of the errors table, and any other error with the last row's message, before it is reported to the callbacks. The next check is still scheduled. @type data_file: DataFile

fiftyone_pipeline_engines.datafile_update_service.DataFileUpdateService.track_local_data_file_changes ( self,
data_file )

Check for local changes to a datafile.

Used by the file system watcher. A file that has been written to is an event. It is first opened for reading, waiting up to WATCHED_FILE_WAIT_SECONDS for a copy still being made, and a file that does not open is reported as AUTO_UPDATE_TIMEOUT without a log entry. Otherwise the refresh takes the same route as the polling one, so the attempt is logged, a failure carries the errors table's message and level, and the result is reported to the update complete callbacks either way. The next check is scheduled whatever happens, so that a later file is still picked up, until the data file is unregistered. @type data_file: DataFile

Check for new data now, download it and refresh the engine with it.

How the check ended is reported to the update complete callbacks, and a failure is then raised to the caller rather than logged. @type data_file: DataFile

Parameters
data_fileDatafile to update @rtype: bool
Returns
: True when the engine was refreshed with new data, or False when there was no new data or the data file's engine has been closed @raises DataUpdateException: When the check or the refresh failed, with the status and message of that failure, and the engine keeps the data it had. The error that caused the failure, if any, is chained as its cause. Any other error is reported as AUTO_UPDATE_UNKNOWN_ERROR and raised as it is. An error raised by an update complete callback is raised as it is, and the callbacks after it are not called.

◆ update_from_memory()

fiftyone_pipeline_engines.datafile_update_service.DataFileUpdateService.update_from_memory ( self,
data_file,
data )

Refresh a data file from the bytes given, without downloading anything.

A data file kept on disk has the bytes written to its path first, as the update route writes a download, and the engine is then refreshed from the file. When the bytes cannot be written, a warning is logged and the engine is refreshed from the bytes, so the file on disk keeps the old data. The result goes to the caller alone, so nothing is reported to the update complete callbacks, and a failure is raised rather than logged. @type data_file: DataFile

Parameters
data_fileDatafile to update @type data: bytes
dataThe new content of the data file @rtype: UpdateStatus
Returns
: AUTO_UPDATE_SUCCESS when the engine was refreshed, or AUTO_UPDATE_NOT_NEEDED, with nothing done, when the data file's engine has been closed @raises DataUpdateException: When the engine could not use the data, with the status AUTO_UPDATE_REFRESH_FAILED, and the engine keeps the data it had. The error that caused the failure is chained as its cause.
