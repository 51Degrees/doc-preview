fiftyone.devicedetection.examples.web.HumanConfidenceLiveTest Class Reference

Detailed Description

Runs the example against the staging cloud service that CLOUD_STAGING_ENDPOINT names, and asks its /passive path as the page does.

The production cloud does not serve HumanConfidenceSource yet, so the tests ask the staging cloud.

Each test reads its own key. The Bespoke key in RESOURCE_KEY_BESPOKE_STAGING, which the staging cloud resolves, has products that offer HumanConfidenceSource, so its answer carries the source Passive and a level. The key in _51DEGREES_RESOURCE_KEY_BASIC has products that don't, so the cloud answers the source as null, with the reason, and the example's answer carries no source. The example is given the key the test checks, as a person running it would set it in _51DEGREES_RESOURCE_KEY. A test is skipped when its key or CLOUD_STAGING_ENDPOINT isn't set, naming the variable, and fails when the answer lacks what it checks. The Bespoke test first fails, naming the variable and the property, when the service's list of the key's properties doesn't include HumanConfidence, then when the service, asked for HumanConfidenceSource with the key, doesn't answer it as Passive. The list isn't asked about the source, as a key can be served the source when a request names it without the list holding it. Keys are never printed.
