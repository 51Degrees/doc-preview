fiftyone.devicedetection.examples.web.HumanConfidence Class Reference

Detailed Description

Human Confidence demo server.

It uses only the JDK's own HTTP server and client, and org.json to read the cloud's answers.

Human Confidence says how likely it is that a person is looking at the page. The demo shows it in three steps.

  1. Passive. This server asks the cloud itself, passing on the visitor's request headers and IP address, and reads HumanConfidenceSource and HumanConfidence from the answer. The request names both properties, so the answer carries them whatever the Resource Key's saved list of properties holds. The server asks rather than reading a level from the page, because a level a browser sends can be forged.
  2. Active. The page loads the 51Degrees client script. When the script completes, HumanConfidenceSource is Active and HumanConfidence holds a sealed value the browser can't read or change.
  3. Redeem. The page hands the sealed value to this server, which sends it with the License Key to hc/redeem and returns the cloud's answer as it came. A sealed value redeems once, within ten seconds. The License Key stays on this server.

Environment variables:

  • _51DEGREES_RESOURCE_KEY, the Resource Key, required
  • _51DEGREES_LICENSE_KEY, a License Key of the same account, needed to redeem
  • _51DEGREES_CLOUD_ENDPOINT, the API base including /api/v4/, which defaults to https://cloud.51degrees.com/api/v4/
  • _51DEGREES_EXAMPLE_HTTP_PORTS, the port to listen on, which defaults to 5151. It may hold a comma separated list, and the example listens on the first port in it

See the README beside this example's pom.xml for the steps.
