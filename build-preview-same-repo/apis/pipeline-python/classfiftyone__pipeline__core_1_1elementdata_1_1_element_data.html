fiftyone_pipeline_core.elementdata.ElementData Class Reference

Detailed Description

Core ElementData class Stores information created by a FlowElement based on FlowData.

Stored in FlowData

An instance is written only by the Flow Element that provides it, or by the Flow Elements that share it, and only while they process. Once they have finished, it is not written again, apart from lazy properties, so it is safe to read from several threads at once, as its values are Python's own managed data. The Flow Data that holds it is still used by one thread at a time.

The exception is Element Data that reads its values from a results instance, such as an on-premise engine's, which references unmanaged memory. Multi-threaded access to a results instance is not supported, for performance reasons, so such Element Data is not safe to use from several threads at once. It takes no lock to make those reads safe. The caller is responsible for thread-safe access, and either gives each thread its own Flow Data or coordinates its own access.

A subclass that holds something to release, such as native results, gives itself a close method. Closing is not a write, so close may set the data's attributes even once it is finished, whether it is called directly or by FlowData.close.

A FlowElement may take its instances from an ElementDataPool, and closing the FlowData gives them back for a later request to reuse. So keeping a reference to ElementData after its FlowData is closed is not supported, because another request may then change its values. Reads are not checked for this.
