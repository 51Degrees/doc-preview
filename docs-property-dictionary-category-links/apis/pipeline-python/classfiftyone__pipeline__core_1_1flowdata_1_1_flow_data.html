fiftyone_pipeline_core.flowdata.FlowData Class Reference

Detailed Description

FlowData is created by a specific Pipeline It collects evidence set by the user It passes evidence to FlowElements in the Pipeline These elements can return ElementData or populate an errors object.

The Element Data is kept in a linked list, newest first. An add puts a new node at the head with a plain write and takes no lock, because no parallel group adds at the same time. Readers follow the links with no lock.

A FlowData is not safe to use from several threads at once. It is used by one thread at a time, and where one is shared across threads, the caller is responsible for any locking, for example by wrapping each use in a lock of its own. A web application creates a FlowData for each request, uses it only in the code that handles that request, and closes it when the request ends.

◆ close()

fiftyone_pipeline_core.flowdata.FlowData.close ( self)

Release the native resources held by the element data in this FlowData, such as the results of an on-premise engine, which keep the engine's data in memory until they are released.

Use a with statement so that this happens as soon as the FlowData is finished with, rather than when the garbage collector next runs.

Only element data with a close method of its own is closed, so element data that needs no cleanup, such as an entry in a results cache, is left alone. Values already read are unaffected.
