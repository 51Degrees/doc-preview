ElementData Class Reference

Detailed Description

Stores information created by a flowElement based on flowData.

Stored in flowData. Element data is written only by the flow element that provides it, or the flow elements that share it, and only while they process. Once they have finished, a write through the element data, or into the contents object a dictionary keeps its values in, throws.

Element data may come from a pool, and go back to it when the flow data that holds it is disposed. Keeping a reference to element data after its flow data is disposed is not supported, because the pool may give the instance to another request. Nothing checks for that on a read.

◆ addLazyProperty()

ElementData::addLazyProperty ( key,
task )
inline

Adds a lazy property, whose value is the result of a task the Flow Element starts while it processes, such as a call to another resource.

The task never reads the Flow Data. Readers wait for it with getAsync, and the Pipeline waits for every task before processing finishes, so a read once processing has finished has the value or the task's error.

Parameters
{string}key the property name
{Promise}task the work that gives the value
Exceptions
{Error}once the flow elements that write the data have finished

◆ recordLazyFailures()

ElementData::recordLazyFailures ( flowData)
inline

Records the failure of each lazy property's task in the Flow Data's errors, as an error of the Flow Element that provides this data, once however many readers meet it.

A reader that meets a failure while the Flow Data is processed calls this, and the Pipeline calls it before processing finishes.

Parameters
{FlowData}flowData the Flow Data being processed
