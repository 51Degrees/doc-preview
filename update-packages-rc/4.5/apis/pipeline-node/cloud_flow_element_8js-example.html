This example demonstrates the creation of a Cloud Engine, a flowElement that gets its results from a remote service rather than working them out itself. Like the other star sign examples it takes a birth date as evidence and gives a starsign, but here the starsign comes from a service.

In a real Pipeline the remote service is the 51Degrees cloud service. So that this example runs anywhere, with no resource key and no network, it starts a small star sign service of its own on this machine, which answers the routes the Cloud Request Engine calls, and points the Cloud Request Engine at it.

The Pipeline has two flowElements:

  1. A Cloud Request Engine, which asks the service which evidence it accepts and which properties it gives, then sends that evidence and keeps the JSON it gets back.
  2. A Cloud Engine for the 'astrology' product, which reads its part of that JSON and gives it as properties, here starsign.
